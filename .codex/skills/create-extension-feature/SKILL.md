# create-extension-feature

## Mission
- Create or modify VS Code extension features while preserving package wiring, generated API usage, and webview safety.

## Domain Knowledge
- Extension source lives under `lurek_2d_extension/src/`.
- Commands live under `src/commands/`.
- Providers live under `src/providers/`.
- Editors and panels own webview features.
- Services own shared IO, indexing, and engine work.
- `lurek_2d_extension/package.json` declares commands, views, menus, settings, and activation.
- A command ID must match the manifest, registration code, and menu or keybinding.
- Engine API data is generated by `tools/docs/gen_extension_api.py`.
- Generated API JSON is not edited by hand.
- The extension host owns filesystem and process access.
- Webviews use typed messages and strict CSP.
- Webviews restore state explicitly.
- Every command, listener, watcher, terminal, and panel is disposable.
- Heavy scans do not run in activation or synchronous provider callbacks.
- Workspace paths come from VS Code URIs.
- Multi-root, remote, empty, and untitled workspaces are valid states.
- Errors distinguish cancellation, invalid project data, missing tools, and extension defects.
- Generated API data and schemas live under `lurek_2d_extension/data/`.
- User-facing actions, settings, activation hooks, and menus all have manifest ownership.
- TypeScript, webview, and manifest changes use the extension `npm run build` target.
- Command and webview behavior is exercised in the Extension Development Host.
- VSIX creation is release work and uses `@vscode/vsce`, not the normal development build.

## Workflow
1. Read the extension contract.
2. Trace the user action from `package.json` to registration and implementation.
3. Identify the owning command, provider, editor, panel, or service.
4. Check whether used API data is generated.
5. Change the smallest TypeScript owner.
6. Add lazy activation and cancellation for long work.
7. Use URI-safe workspace access.
8. Add every registration to the disposal lifecycle.
9. Define typed host and webview messages.
10. Apply strict CSP to webview assets.
11. Wire exact IDs through manifest, registration, menus, and settings.
12. Regenerate engine-derived API data when its source changed.
13. Run `npm run build` from `lurek_2d_extension/`.
14. Run extension tests.
15. Test in an Extension Development Host.
16. Test reload, empty workspace, missing engine, and cancellation.
17. Verify command visibility and enablement contexts.
