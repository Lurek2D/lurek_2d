# VS Code Contract

Adds local rules for `extension/vscode/`.

## Mission & Scope
- Own the VS Code extension codebase, including commands, sidebars, and webviews.
- Maintain generated API definitions, local settings, and integration scripts.
- Keep strict CSP and robust webview message passing.

## Files
- `src/commands/`: Command entry points and menu wiring.
- `src/providers/`: Sidebars, trees, and autocomplete providers.
- `src/editors/`: Custom editors and webview panels.
- `data/`: Autocomplete data and generated schemas.

## Rules
- Every user-facing action, configuration setting, and activation hook must be declared in `package.json`.
- All webview panels must explicitly configure and enforce a strict `Content-Security-Policy` header.
- Never write ad hoc JSON schemas; consume api descriptors generated by `tools/docs/gen_extension_api.py`.
- Keep editor logic decoupled. Move heavy work to the engine or background scripts.

## Workflow
- Build the bundle via `npm run build` after editing TypeScript source, webview assets, or extension manifest wiring.
- Verify visual panels and commands inside the VS Code Extension Development Host when UI, commands, or message passing behavior changes.
- Package and lint the extension using `npx @vscode/vsce package --no-dependencies --allow-missing-repository` only when release packaging or VSIX validation is part of the task.
