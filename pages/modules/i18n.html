    I18N¶

    Purpose¶

    Manages translation catalogs, plural rules, and locale-aware formatting.

    When To Use¶

    • Catalog loading, fallback lookup, interpolation, and plural handling let UI and content live as translation data instead of hardcoded language branches.
    • Formatting helpers extend the module beyond plain strings so numbers, dates, and other user-facing values can follow locale rules through the same API surface.
    • Runtime locale switching and coverage-style analysis make the module useful for both shipped UX and development workflows.

    Minimal Example¶

    From the lurek.i18n.loadTable example block:

    do
    seed_catalog()
    local had_en = lurek.i18n.hasLanguage("en")
    lurek.i18n.loadTable("runtime_ui", { menu = { resume = "Resume run" }, ui = { apply = "Apply" } })
    lurek.i18n.setLanguage("runtime_ui")
    local resume = lurek.i18n.t("menu.resume")
    i18n_log("loadTable had_en=" .. tostring(had_en) .. " runtime_ui=" .. tostring(lurek.i18n.hasLanguage("runtime_ui")) .. " resume=" .. resume)
end

    Common Patterns¶

    • Start with lurek.i18n.buildIndex when exploring this module.
    • Start with lurek.i18n.categories when exploring this module.
    • Start with lurek.i18n.detectLocale when exploring this module.
    • Start with lurek.i18n.formatDate when exploring this module.
    • Start with lurek.i18n.formatNumber when exploring this module.

    API Reference¶

    • Full generated API reference: docs/api/lurek.md
    • Runnable example owner: content/examples/i18n.lua

    Summary¶

    • The i18n module is the localization surface for projects that want translated text, locale-aware formatting, and language switching to behave as one system.
    • Catalog loading, fallback lookup, interpolation, and plural handling let UI and content live as translation data instead of hardcoded language branches.
    • Formatting helpers extend the module beyond plain strings so numbers, dates, and other user-facing values can follow locale rules through the same API surface.
    • Runtime locale switching and coverage-style analysis make the module useful for both shipped UX and development workflows.
    • Missing translations, fallback chains, and locale coverage matter because localized projects need predictable degradation instead of silent English-only gaps.
    • Read it as the path from localization data to final user-visible text at runtime.

    This module is mostly self-contained inside the Feature Systems group. Cross-module behavior should stay in the referenced Rust source files and Lua bindings rather than being duplicated here.

    lurek.i18n.buildIndex¶

    Builds a word-to-keys search index from the catalog.

    lurek.i18n.buildIndex()

    Returns

    Type Description
    table Map table from normalized words to arrays of translation keys.

    Example

    do
    seed_catalog()
    local index = lurek.i18n.buildIndex()
    local hello_keys = index.hello or {}
    local start_keys = index.start or {}
    local first = hello_keys[1] or "none"
    i18n_log("buildIndex hello_count=" .. tostring(#hello_keys) .. " start_count=" .. tostring(#start_keys) .. " first=" .. first)
end

    lurek.i18n.localeCoverage¶

    Returns missing translation keys for all locales compared to a reference locale.

    lurek.i18n.localeCoverage(reference)

    Parameters

    Name Type Description
    reference string Locale code used as the coverage reference.

    Returns

    Type Description
    LI18nLocaleCoverageResult Array of gap rows with key and missing_in fields.

    Example

    do
    seed_catalog()
    lurek.i18n.loadTable("cov_en", { ui = { ok = "OK", cancel = "Cancel" }, hud = { ready = "Ready" } })
    lurek.i18n.loadTable("cov_pl", { ui = { ok = "OK" } })
    local gaps = lurek.i18n.localeCoverage("cov_en")
    local first = gaps[1]
    local missing = first and #first.missing_in or 0
    i18n_log("localeCoverage gaps=" .. tostring(#gaps) .. " first_key=" .. tostring(first and first.key or "none") .. " missing_count=" .. tostring(missing))
end

    local apply = lurek.i18n.t("ui.apply")
    local exists = lurek.i18n.hasKey("ui.apply")
    i18n_log("setKey exists=" .. tostring(exists) .. " apply=" .. apply)
end

    lurek.i18n.tGender¶

    Translates a gender-specific key variant when present, then falls back to the base key.

    lurek.i18n.tGender(key, gender, vars)

    Parameters

    Name Type Description
    key string Base translation key.
    gender string Gender suffix appended to the key.
    vars? table Interpolation variables.

    Returns

    Type Description
    string Gender-specific or fallback translated text.

    Example

    do
    seed_catalog()
    lurek.i18n.setKey("en", "title", "Captain {name}")
    lurek.i18n.setKey("en", "title.masculine", "Sir {name}")
    local masculine = lurek.i18n.tGender("title", "masculine", { name = "Alex" })
    local fallback = lurek.i18n.tGender("title", "neutral", { name = "Alex" })
    i18n_log("tGender masculine=" .. masculine .. " fallback=" .. fallback)
end

    lurek.i18n.unloadTable¶

    Removes all translations for a locale from the catalog.

    lurek.i18n.unloadTable(locale)

    Parameters

    Name Type Description
    locale string Locale code to unload.

    Returns

    Type Description
    boolean True when a locale table was removed.

    Example

    do
    seed_catalog()
    lurek.i18n.loadTable("tmp_i18n", { debug = { label = "Debug overlay" } })
    local loaded = lurek.i18n.hasLanguage("tmp_i18n")

    local still_loaded = lurek.i18n.hasLanguage("tmp_i18n")
    i18n_log("unloadTable loaded=" .. tostring(loaded) .. " removed=" .. tostring(removed) .. " still_loaded=" .. tostring(still_loaded))
end
