## Summary

- The `i18n` module is the localization surface for users who want translated text, locale-aware formatting, and language switching to behave as one system.
- Catalog loading, fallback lookup, interpolation, and plural handling work together here so UI and content can be expressed as translation data rather than as hardcoded language branches.
- Formatting helpers extend the module beyond plain strings: numbers, dates, and other user-facing values can follow locale rules through the same API surface.
- Runtime locale switching and coverage-style analysis make the module useful for both shipped UX and development workflows, because translators, QA, and UI authors can verify behavior without inventing separate language utilities.
- Read this spec as the path from localization data to final user-visible text: the module resolves the correct string and format, and neighboring systems display the result.
