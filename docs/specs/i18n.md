## Summary

The `i18n` module is the localization core for language-aware runtime text. It stores translation catalogs by locale, resolves keys through fallback chains, and gives scripts one stable API for multilingual output.

It supports practical translation behavior beyond basic key lookup. Templates can interpolate runtime values, plural forms can follow locale rules, and missing keys can degrade gracefully through configured fallback locales.

Regional formatting is part of the same surface. Number and date helpers apply locale-sensitive output rules, so UI and tool text can match language and region expectations without custom formatting code in every module.

The module also helps QA and maintenance with coverage and catalog inspection utilities. In practice, `lurek.i18n` provides one complete localization contract: load catalogs, translate safely, format region-aware values, and audit translation completeness.

## Files

### catalog.rs

- Provides a locale-first translation catalog that serves runtime string lookup with fallback chains.
- Stores per-locale key tables and active language state so content can switch language without rebuild.
- Performs resilient key resolution that walks configured fallback order before reporting missing entries.
- Supports import flattening from TOML and JSON trees into dot-path lookup keys for uniform access.
- Computes coverage gaps across locales to expose untranslated keys during QA and localization passes.
- Offers category grouping and search-style scans that help tools inspect large translation inventories.
- Includes locale validation, RTL detection, and system-locale discovery for startup language selection.
- Keeps lightweight caches to accelerate repeated text and word lookups in hot UI translation paths.

### format.rs

- Formats locale-facing numbers and dates into human-readable strings for UI presentation.
- Chooses decimal and thousands separators from locale prefixes to match regional reading habits.
- Converts epoch-based day counts and timestamps into calendar components and formatted date output.
- Supplies ISO, short, and long date renderings for compact HUD and verbose panel contexts.
- Encodes month-name mapping logic used by textual date labels in localized interfaces.

### interpolation.rs

- Expands localized template text by replacing `{name}` placeholders with runtime values.
- Preserves unknown tokens and supports escaped braces so authored text stays readable under partial data.
- Provides both map-driven and pair-list substitution flows for ergonomic caller integration.
- Keeps output assembly linear and allocation-light for frequent UI string rendering.

### mod.rs

- High-level i18n module entry point combining catalogs, formatting, interpolation, and plural rules.
- Re-exports locale utilities and core types so callers consume localization features from one surface.
- Defines the integration spine for language detection, lookup, and human-friendly output shaping.

### plural.rs

- Encodes plural category logic used to choose grammatically correct translation variants by count.
- Maps quantity values to form keys with dedicated paths for English-style and Slavic-style rules.
- Supports stable key conversion so plural forms align with translation-table naming conventions.
- Provides fallback-aware pluralized string selection when exact form variants are absent.
